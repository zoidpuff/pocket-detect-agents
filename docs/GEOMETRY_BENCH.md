## API in one paragraph

`pocketdetect.geometry`: `sas_points`, `grid_candidates`, `occupancy_grid` + `ray_buriedness` (multi-scale, soft occlusion via per-atom weights), `psp_counts` (LIGSITE prefilter), `cascade_mask`, `neighbor_features` / `protrusion` (radius + Gaussian sums of any (N,F) atom property matrix, e.g. `atom_class_matrix`), `smooth_point_values`, `single_linkage` / `mean_shift` / `quick_shift`, `canonical_frame`, `brick_boxes`; each has a `*_torch` twin taking a `batch` vector (Triton fast path, PyTorch fallback). `compute_point_features` (CPU) and `compute_point_features_batch_torch` (GPU, many structures per call) run the whole pipeline configured by `FeatureConfig`. Tests: `tests/test_geometry_*.py`.

**Caveat:** the node is shared (other agents/jobs run concurrently on the same cores), so multi-threaded CPU timings are noisy; all values are the minimum over repeats. Structure parsing (gemmi) is excluded and listed separately (`load_ms` in the JSON).

Settings = `FeatureConfig` defaults: `points=sas`, `probe=1.4`, `n_sphere=30`, `grid_spacing=1.0`, `grid_max_dist=5.0`, `psp_length=8.0`, `psp_dirs=7`, `min_psp=2`, `subsample=2`, `n_rays=60`, `ray_lengths=[8.0, 12.0, 20.0]`, `occ_spacing=1.0`, `ray_step=1.0`, `ref_length=2.0`, `radius_scale=1.0`, `radius_pad=0.0`, `nb_radii=[4.0, 6.0, 8.0, 10.0, 12.0]`, `sigmas=[2.0, 4.0]`, `canonical_frame=True`, `max_voxels=16777216`, `max_voxels_gpu=134217728`.

Columns: `sas` SAS points (30/atom); `grid` solvent-shell grid candidates (1 Å, <= 5 Å from an atom centre, probe 1.4 Å); `occ` absorption grid; `psp_grid` LIGSITE 7-direction PSP count on all grid points; `rays_sas` 60-ray buriedness at L = 8/12/20 Å on the SAS points; `neighbors_sas` 13 atom classes x (5 radii + 2 Gaussians) on the SAS points; `cluster_sl` single linkage (2 Å) of SAS points with b12 > 0.6. `pipe_sas` / `pipe_cascade` = complete per-point feature pipeline (`compute_point_features`, canonical PCA frame, points + PSP + rays + neighbours); cascade = grid shell -> PSP >= 2 or 2 Å sub-lattice -> rays/neighbours on survivors.

## Notes

- GPU pipeline rows include host->device copy of the atoms, PCA framing on the host and device->host copy of all features; per-primitive GPU rows start from device tensors.
- GPU fast path = Triton kernels (SAS burial test, voxel stamping, PSP, ray marching, neighbour accumulation); pure-PyTorch fallbacks (use_triton=False) agree with them (tested) but are 5-150x slower.
- Single-structure GPU calls are launch/sync-latency bound; batching many structures per call is how the GPU reaches its throughput.
- Rays use step = voxel = 1 Å by default (review round 1); the occlusion radius is the bare vdW radius (`radius_pad=0`), to be tuned on dev data.
- numba kernels are compiled with cache=True: the 'cold' JIT cost is paid once per installation (or after source changes); 'cached' is the per-process start-up cost afterwards.
- CPU multi-thread scaling is limited by the shared node (other jobs on the same cores) and OpenMP barrier spinning at 64 threads; for throughput use one single-threaded process per core.
