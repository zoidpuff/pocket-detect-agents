## Notes

- Fast backend = exact re-implementation: Numba ports of formation / residues / descriptors / NMS / metal candidates / metal geometry, LightGBM-free forests (bit-identical), fp64-exact Triton kernels on GPU.
- The reference ray march and neighbour sums are already Numba; exact re-implementations gave no CPU speed-up, so the CPU fast path reuses them. Reaching <=70 ms/core needs method-side changes (fewer rays / shorter max length / fewer scored points / smaller point model), see the stage table.
- GPU mode: one process per GPU; each has its own pool of single-threaded CPU workers for parsing, host prep (canonical frame, metal candidates) and post-processing (formation, ranking, NMS, writing).
- Thread budget: <= 32 worker processes in total (shared 4096-thread user limit).
